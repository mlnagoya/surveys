## 比較条件・留保

- ContextBench は、入力操作が必ず会話履歴に入ってからエージェントが処理する設計です。
- 問題が要求する保持内容は上限内に収まるよう生成されます。外部ファイルに保存しただけでは得点されず、回答などを履歴に戻す必要があります（pp.18–20）。
- GPT-5.4 の pilot 評価では、各手法に同程度の詳しさで専用の説明と skill を与えます。指示文最適化の「指示なし」初期値とは条件が異なります（pp.20–21、23）。
- CLM の上限直前の編集リマインダーや、上限超過時の rollback/retry も設定に含まれます。管理能力が完全に自律化しているとまでは解釈しません（pp.21–22、27）。
- 数学最適化は各手法1回の実行で得た最良値です。EdgeBench は公開48課題のうち10課題です（p.22）。
- Software World は実行命令数に基づく17の未使用 CPU benchmark の幾何平均で、実時間の高速化と同一ではありません。壊れた benchmark は1.0として扱います（pp.22–23）。
- 指示文最適化では開発用102例で選択し、assisted evolution のテスト102例×3 seed は選択後に一度だけ評価します。Qwen のコスト集計は予算内で完了した実行に限られ、失敗込み全体平均とは区別が必要です（p.23）。
- RL は3,040の OpenResearcher prompt で70 step 学習し、別の500問で checkpoint を選択します。BrowseComp-Plus の830問で評価します（pp.23–24）。
- p.24 の追加学習なし9Bの39.9%と、表2の学習前28.8%は別設定の結果です。まとめでは連続した学習前後として扱っていません。
- 32K の EdgeBench では subagent 有無が44.2対44.6点、128K では50.2対47.3点です。並列化は常に有効とは言えません（pp.8、25）。
- 本文の prefix-reuse FLOPs は理論的な演算量の推定です。埋め込み・出力層・linear attention の状態更新・正規化などは算入しておらず、API 料金や実行時間と同じ指標ではありません（pp.17–18）。
- SCR の旧 cache は編集前の prefix に依存します。位置補正しても内容の依存は消えず、完全な再計算との等価性はありません（pp.14–16）。
- SCR は最大6区間を再利用します。K の感度評価は64問で行い、主要結果は830問です（pp.15–16）。
- SCR が prefix 一致以外で再利用する7.8%の prompt tokens のうち、5.3ポイントは reasoning tokens 除去、2.5ポイントはその他の編集に由来します。効果の全てが CLM 固有ではありません（p.16）。
- 著者の今後の方向性は、RL の拡大と既存の実行基盤に埋め込まれた方策の蒸留です。まとめでは主要な限界を優先しました（p.10）。

## 原文内の表記差

本文・図と付録のどちらかを推測で訂正せず、以下を原文の不整合として残しています。
実装を再現して解消したものではありません。

- 図5・図17および本文は32Kの上限と記載しますが、付録Eの BrowseComp-Plus は23,560 tokens と記載します（pp.7、22、24）。
- 図5のキャプションは100 turns と記載しますが、付録Eの TerminalBench 2.1 は64 turns、TBLite も同じ制限と記載します（pp.7、22）。
- CLM の編集ターンは BrowseComp-Plus の100-turn制限や RL の80-turn制限から除外されます。通常ターンだけを揃えても全 model call 数が同じとは限りません（pp.22、24）。
- EdgeBench の subagent は本文で最大5、付録Eで最大6同時と記載します（pp.8、22）。
- RL の本文には比較側も同じ recipe という説明がありますが、付録Eには CLM の効率 advantage と補助ペナルティ、Summary の task reward の違いが書かれています。図21には両者について FLOPs 報酬の有無も示されています（pp.3、24、26）。
- RL の図21は評価を32Kと記載しますが、付録Eの28K・80 turns と28,672-tokenでの圧縮・100 turnsは rollout 設定として示されています。まとめでは学習・評価の上限が完全一致すると断定していません。
